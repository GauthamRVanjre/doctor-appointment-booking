## Tool mechanism finding

Current official docs: https://docs.agora.io/en/ai/build/tools/custom-tools

Agora supports managed synchronous GET/POST calls to HTTPS endpoints, with JSON Schema arguments and server-side authentication headers. A custom OpenAI-compatible endpoint is an alternative for a server-owned LLM/tool loop, not a requirement for business execution. Custom LLMs do not support the managed custom-tool mechanism; choose one path deliberately. The optional baseline proxy currently implements neither booking tools nor an execution loop.

Prefer Next.js server routes, subject to verifying SDK 2.9.0 types and session identity/approval binding before implementation. Local endpoints need a development HTTPS tunnel for Agora cloud access. No tunnel has been installed or exposed. Managed tool names currently allow only letters and numbers, so the requested snake_case internal names need documented external aliases if using managed calling. No automatic tool retries are promised by the docs; booking must remain idempotent anyway.

## Manual acceptance before closing Milestone 1

From baseline run `pnpm dev`, then open http://localhost:3000. Use fictional non-medical speech with the unmodified Ada assistant. Start a conversation and allow microphone access. Verify you hear its greeting, speak a question, hear a relevant spoken answer, and see both sides in the live transcript. End the session and verify audio stops and microphone releases. Report errors without copying tokens or secrets. Compilation and a returned RUNNING string alone do not prove these behaviors.
